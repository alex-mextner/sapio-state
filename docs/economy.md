# Economy and commons

Status: design hypotheses to test

## No-general-tax hypothesis

The proposal explores whether a digital polity could operate without a broad compulsory tax.

That is not assumed to be feasible. The repository treats it as a budget constraint that must be tested against the actual cost of public goods, dispute resolution, security, infrastructure, research, and social commitments.

## Candidate funding sources

Possible sources include:
- optional paid services;
- commercial organizations owned wholly or partly by the network;
- fees for scarce or high-cost services;
- endowment income;
- voluntary contributions;
- grants and research partnerships;
- protocol fees for shared infrastructure;
- usage charges where they directly internalize a commons cost.

Each source has different capture and fairness risks and should be modeled explicitly.

## Commons

A no-general-tax model does not imply no rules.

Shared resources may require:
- quotas;
- congestion pricing;
- deposits/bonds;
- polluter-pays rules;
- access limits;
- auctions;
- cooperative ownership;
- maintenance obligations.

The mechanism should match the resource rather than rely on one universal economic rule.

## Resident token

The project proposes that a new resident may receive an initial allocation of a network token.

Questions that must be resolved before implementation:
- What utility does the token provide?
- Is supply fixed, adaptive, or governance-controlled?
- Who can issue/burn?
- Can it be redeemed for anything?
- Does it carry governance rights?
- How is theft/recovery handled?
- Is it transferable?
- How are sybil attacks prevented?
- How is early-holder concentration limited or disclosed?
- What financial regulation applies in each jurisdiction?

The repository should avoid describing the token as an investment or legal tender unless that is legally accurate.

## Commercial organizations

A design objective is to place activities that can operate competitively into ordinary commercial organizations rather than a central administration.

Open questions:
- where competition is technically possible;
- where network effects create natural monopoly;
- which services need universal-access obligations;
- how conflicts between a regulator and a commercial affiliate are separated;
- how public interfaces remain open to competing implementations.

## Public budget

Even if tax revenue is zero, the system still needs a transparent budget.

Every recurring public obligation should publish:
- owner;
- service-level target;
- annual cost;
- funding source;
- reserve;
- dependencies;
- failure mode if funding ends;
- sunset/review date.

## Simulation

Before launch, model at least:
- resident growth;
- zero/low/medium commercial revenue;
- adverse years;
- infrastructure incidents;
- legal/compliance costs;
- research-programme overruns;
- commons depletion;
- token volatility if a token exists.

A funding model that works only during rapid growth is not considered validated.
